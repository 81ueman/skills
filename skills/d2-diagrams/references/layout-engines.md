# レイアウトエンジンの選び方（dagre / elk / tala）

D2 は同じソースから `--layout` でエンジンを差し替えられる。エンジンによって図の「思想」が違うので、用途で選ぶ。

## ひとことで

| エンジン | 一言でいうと |
| --- | --- |
| `dagre` | **階層に並べることを最優先する軽量な Sugiyama 系**。D2 の既定 |
| `elk` | **同じ階層型だが、制約・ポート・配線・コンテナまで本格的に扱う Sugiyama 系** |
| `tala` | **そもそも階層に縛られず、人間がホワイトボードに描きそうな 2D 配置を探索する**（v0.9.0+ で同梱） |

D2 公式も dagre/elk を hierarchical、tala を software architecture 向けの orthogonal（直交）layout として区別している。

## アルゴリズムの系統

**dagre と elk はどちらも Sugiyama 系の階層レイアウト**（特に dagre は Graphviz DOT アルゴリズムに基づく）。処理の骨格は同じ:

```text
cycle breaking → layering → crossing minimization → node placement → edge routing
```

まず「各ノードは何段目か」を決め、辺をできるだけ一方向に揃える。だから図が一方向に伸びやすく、**縦長/横長の帯**になりがち。

**tala は別系統**。段（layer）という概念から始めない:

```text
構造認識（tree / cluster / sequence / hierarchy / hub）
  → 配置探索（複数シード + 多目的コスト評価）
  → 直交配線（可視性グラフ上の経路探索）
  → スコアで最良を選択
```

「この部品群を 2D のどこに置けば全体が美しいか」を、対称性・距離・フロー・クラスタリング・交差などを同時に評価しながら探す。だから人間が白板に描いたような 2D 配置になる。

| エンジン | 最初に考えること | 主目的 |
| --- | --- | --- |
| `dagre` | 各ノードは何段目？ | フローをきれいに |
| `elk` | 何段目？順番？ポート？配線？コンテナ？ | 制約を守りつつ階層をきれいに |
| `tala` | この部品群を 2D のどこに置けば美しい？ | 人間っぽいアーキテクチャ図 |

## 公式の長所・短所（D2 docs より）

### dagre
- **長所**: 非常に速い / Mermaid で使われている実績 / 結果が総じて良好 / Graphviz の論文に基づく / 階層レイアウトが得意
- **短所**: 公式 docs は JS 版 dagre を「2018年で開発停止」としている（ただし D2 v0.9.0 が同梱するのは保守が続く Go ポート **Dagro**）/ 稀に不可解な配線 / 図が階層的でなくても強制的に階層化 / コンテナの子→別コンテナは非対応（D2 が shim で対応）/ **複数セグメントの辺が曲線**になりギザギザすることがある

### elk
- **長所**: きれいな直交配線 / 高いカスタマイズ性 / 速い / 交差最小化が得意 / **コンテナ間配線が dagre より得意** / 活発にメンテ / `sql_table` を正確な列に接続
- **短所**: dagre と同じく**厳密に階層型** / 不要な曲がりが入ることがある / **対称性はほぼ考慮しない**
- **補足**: `layered` が既定（上の長所・短所は `layered` のもの）。`--elk-algorithm`（`--layout=elk` と併用）で `force` / `stress` / `mrtree` / `radial` も選べるが、直交配線や `sql_table` の列ルーティングなど `layered` の機能は使えなくなる。`mrtree` / `radial` は木・階層を期待し、`radial` は木でない入力で失敗することがある

### tala
- **長所**: 階層・木・放射に縛られない汎用の直交エンジン / `top`・`left` で座標固定 / **対称性を好む** / コンテナを最初から考慮 / **コンテナごとに `direction`** / **`near` を別の shape に指定できる** / `sql_table` が正確な行に接続 / 動的ラベル配置 / グリッドセルも tala の配線を使う
- **短所**: **ランダム性がある**。ラベルを少し変えただけで全体配置が激変しうる

## D2 機能の対応差（重要）

| 機能 | dagre | elk | tala |
| --- | --- | --- | --- |
| `near` を shape（オブジェクト）に指定 | ✗ | ✗ | **✓** |
| コンテナの `width` / `height` | ✗ | ✓ | ✓ |
| `top` / `left` で座標固定 | ✗ | ✗ | **✓** |
| 祖先→子孫への接続 | **✗** | ✓ | ✓ |
| コンテナごとの `direction` | ✗ | ✗ | **✓** |
| 全体の `direction` | ✓ | ✓ | ✓ |

階層型（dagre/elk）は図全体で1方向しか向けられない。コンテナごとに方向を変えたい、座標を固定したい、`near` を shape で指定したい場合は tala 一択。

ただし未対応エンジンでの挙動は一様でない。`near`(shape)・`top`/`left`・祖先→子孫は**コンパイルエラーで描画できない**が、コンテナごとの `direction` は**無言で無視**される。tala 用に書いたソースは dagre/elk でエラーになりうる（`d2 validate` では検出されない）。

## 図タイプ別の第一候補

あくまで目安。同じソースを複数エンジンで描いて比べるのが確実。

| 図 | 第一候補 |
| --- | --- |
| Leaf-Spine / Clos、packet flow、BGP 依存関係 | `dagre`（大規模・コンテナ多めなら `elk`） |
| port/link が多く、コンテナ階層が複雑 | `elk` |
| WAN overview、hybrid cloud、サービス+NW+DB が混在 | `tala` |
| 座標を固定したい / 人間が Visio・draw.io で描く感じ | `tala` |

判断の本質: **dagre/elk は「グラフ理論寄り」、tala は「ダイアグラムデザイン寄り」**。

長く流れる DAG や方向が本質的な図は dagre/elk が有利。tala は非階層的なトポロジ（中心ノードに複数サイトが接続する等）で強みが出る。ただし放射状（スター）に配置されるとは限らず、tala も整った直交配置になる。

- **閉路が主題の依存関係図**: Sugiyama は閉路を辺の逆転で表現するため、循環が分かりにくいことがある（例: BGP の AS 循環）。その場合は tala も試す
- **循環・自己ループ自体は全エンジンで描ける**（非対応なのは祖先→子孫の接続）

## 速度

小さい図では大差ないが、**大きくなるほど tala は遅い**（非線形にスケール）。**100 ノード前後で配線の作業上限に達し、失敗することがある**（`all TALA seed attempts failed ... work limit exceeded`。上限を上げるフラグはない）。大きい図は dagre/elk。

## 注意

- tala は **D2 v0.9.0 以降は同梱**（`--layout tala`）。それ以前は別途プラグインが必要だった。古い README/記事には「有償・別途インストール」と書いてあることがあるが現在は不要
- tala は**ランダム性**を持つ。同じシード・同じ入力なら再現する（既定シード `1,2,3`）。ソース中の `tala-seeds` は CLI フラグより優先される。図をバージョン管理しているなら、生成し直して差分をレビューする運用にする
- D2 が同梱するのはいずれも **Go ネイティブ実装**（dagre は Dagro、elk は elk-go）。本家の JS 版 dagre.js / elkjs そのものではない点に注意
- 「1つエンジンに固定」しなくてよい。同じ記述のまま図タイプごとに `--layout` を切り替えるのが D2 の設計に合う。ただし `top`/`left` や shape への `near` を含むソースは dagre/elk でエラーになる点に注意（上の「D2 機能の対応差」表を参照）
- `top`/`left` は**必ず両方**指定する（片方だけだと `must set top and left together` エラー）
- エンジン差の確認は ASCII ではできない（dagre/elk の ASCII は同一になりがち）。SVG/PNG で見る
- `d2 --check` は既定 dagre で評価する。tala 専用機能を含むソースは `d2 --check --layout tala` を使う

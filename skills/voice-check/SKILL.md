# 音声入力チェック＆整形スキル

音声入力で文字起こしされた指示文は、同音漢語の誤認識や文の崩れにより、**日本語として不自然になったり、元の意図が伝わらなくなったり**することがある。このスキルは、そのような指示文を次の3ステップで扱う。

## ワークフロー

### Step 1. 日本語チェック(崩れの検知)

貼り付けられた指示文を、次の観点で検査する。実害のある崩れか、無害な言い換えかを**必ず区別**する(実害のある崩れだけを修正・確認対象にする)。

**実害のある崩れ(検知して修正対象にする)**:

- **同音漢語の誤認識**: 音が近い別の漢語にすり替わる。例: 要件→容器 / 修正→消費 / 動作確認→動作制限 / 保存→子供 / 今朝→記者
- **指示語が先行詞を持たない**: 「そうしてください」「それしてください」で「そう」「それ」が指す動作が文中に無い。例: 「分からない点があったら、そうしてください」
- **助詞の変化による意味の変質**: 「要件を整理」→「容器に整理」のように、助詞(を→に等)が変わって意味が壊れる
- **指示の要素の欠落・変質**: 「〜して、〜してください」という連続動作・複数指示のうち、一部の動作が別物に置き換わる
- **文脈に噛み合わない名詞**: ドメイン知識から「この文脈にこの単語は不自然」と判断できるもの(例: 文書作業なのに「子供ボタン」)

**無害な言い換え(検知しても修正不要・そのまま通す)**:

- 同義の言い換え: 照合→比較 / っぽい→ようです / あるので→ありますので / 返ってきたら→返った場合
- 助詞の自然な言い換え: 〜の中の→〜内の / 読み込んで→読み込み
- 同義語の補足: その、など
- 句点・読点の増減(意味が変わらない範囲)

### Step 2. 整形(自然な指示文へ)

実害のある崩れを、元の意図を推定して自然な指示文に直す。修正するときは**なぜそう直したかを明記**する(例: 「『容器』は『要件』の誤認識だと思われます」)。

- 認識できなかった元の語は、文脈とドメイン知識から推定する
- 日時・期限・対象・動作・条件がすべて明確になるよう整形する
- 曖昧で元の語が一意に推定できない場合は、その箇所を明示してユーザーに聞き返す(勝手に推測して実行しない)

### Step 3. 確認の提示(実行前)

整形した指示文を提示し、「**この内容でよろしいですか?**」とユーザーに確認を求めてから実行する。ユーザーの承認が得られるまで、指示を実行してはならない。

## チェック・整形の出力形式

ユーザーには次の段取りで返答する。

1. **元の文と整形後の比較表**(どこの単語がどう変わったか分かるように)
2. **判定**(日本語として自然か / 意図が伝わるか / 危険度)
3. **実際に実行する指示文**(整形済みで、ユーザーの確認を求める形)

## ユーザーが自らチェックするための基礎知識(必要に応じて案内)

音声入力で崩れやすいのは、ほぼ次のどちらかに限られる:

- **短い・同音になりやすい2文字漢語**(要件/容器・修正/消費・保存/子供・今朝/記者 など)
- **指示語への置き換え**(「そう」「それ」など)

対策は3つ:
1. 短い漢語はゆっくりはっきり発音する
2. 崩れやすい語は言い換える(「今朝」→「今日の朝のデータ」など)
3. 認識結果に「変な名詞」がないかだけ目を通す

## 注意

- このスキルは**日本語**の音声入力指示文を対象とする
- 実行の承認はユーザーが行う。ユーザーの承認前に実行してはならない
- 推測の自信度が低い箇所は、聞き返しを優先する

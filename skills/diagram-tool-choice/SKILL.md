# 図ツールの選定（d2 / Mermaid）

図を書き始める前に、このスキルで **d2** と **Mermaid** のどちらを使うかを決める。
決定したら必ず対応するスキルをロードしてから書く:

- d2 を選んだ → `d2-diagrams`
- Mermaid を選んだ → `mermaid-diagrams`

## 判断軸

| 判断軸 | D2寄り | Mermaid寄り |
| --- | --- | --- |
| ネットワーク/インフラ構成 | ◎ | ○ |
| 階層・コンテナが多い | ◎ | ○ |
| Sequence | ○ | ◎ |
| ER/Class/State | ○ | ◎ |
| README埋め込み | ○ | ◎ |
| CLI/ASCII重視 | ◎ | △ |
| 見た目・配置の制御 | ◎ | ○ |
| GitHubだけで完結 | △ | ◎ |

## 迷ったときの既定ルール

1. **インフラ/ネットワーク構成、ネストの深い階層、レイアウトを詰めたい** → **d2**
2. **フローチャート、シーケンス、ER、クラス、状態遷移、ガント、マインドマップ** → **Mermaid**
3. **GitHub の README/Issue/PR にそのまま描画したい** → **Mermaid**
   （```` ```mermaid ```` フェンスがそのまま描画される。d2 は画像をコミットするか Actions でのレンダリングが要る）
4. **ターミナル/CLI や SSH 先で見たい、ASCII が欲しい** → **d2**
   （`--ascii-mode` でネイティブ ASCII/Unicode 出力。Mermaid は `mermaid-ascii` で ASCII 化できるが対応図種は限られる）
5. **上記に当てはまらない / 短時間で済ませたい** → **Mermaid**（記法が簡潔で導入も 1 コマンド）

## 早見表

| 作りたい図 | 第一候補 |
| --- | --- |
| ネットワーク/DC 構成、CLOS、物理・論理トポロジ | d2 |
| システム全体構成、依存関係、多段の階層 | d2 |
| 処理フロー、判断分岐、ワークフロー | Mermaid（flowchart） |
| シーケンス（API/プロトコル/メッセージング） | Mermaid（sequenceDiagram） |
| ER 図、クラス図、状態遷移 | Mermaid |
| ガント、ロードマップ、マインドマップ、タイムライン | Mermaid |
| ターミナルで見る / コメントに貼る / ASCII が欲しい | d2 |

## 併用してよい

1 つの成果物で両方使って構わない:

- **インフラ構成図は d2** で画像化（PNG/SVG）して README から参照
- **処理フローや API シーケンスは Mermaid** で README 内にインライン
- どちらもソースはテキストなので、図のソースも一緒にコミットして差分を追えるようにする

## ワークフロー

1. 上の表でツールを決め、**選んだ理由を一言添える**
2. 対応スキル（`d2-diagrams` / `mermaid-diagrams`）をロードする
3. ソースを書く
4. **必ずレンダリングして検証する**（構文エラーはレンダラが教える）
5. 用途に応じて出力形式を選ぶ
   - README/GitHub → Mermaid フェンス、またはレンダリング済み SVG/PNG
   - ローカル閲覧 → `open -a Preview` で PNG
   - ターミナル → ASCII（d2 は `--ascii-mode`）

## どちらでもよい場合

判断軸が拮抗したら、次の順で決める:

1. GitHub のテキスト内で完結させたいか → yes なら Mermaid
2. レイアウトや見た目を細かく制御したいか → yes なら d2
3. それでも決まらなければ Mermaid（導入済みで速い）
